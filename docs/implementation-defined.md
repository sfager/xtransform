# Implementation-defined behaviour

Where the XSLT 2.0, XPath 2.0 or F&O specifications leave behaviour implementation-defined,
record XTransform's choice here: the spec reference, the choice, and why.

| Spec reference | Item | XTransform's choice | Reason |
| --- | --- | --- | --- |
| XSLT 2.0 §12.3 `lang` | Default and supported languages for `xsl:number` | English only. An absent or unsupported `lang` is treated as `en`, which the spec allows ("the language it would use with lang omitted"). | Number words and ordinals for other languages need per-language tables; tracked as a follow-up to P4-07. |
| XSLT 2.0 §12.3 `w`, `W`, `Ww` | English cardinal words | `zero`, `twenty-one`, `one hundred and five` (British "and" after hundreds and before a final group below one hundred); supported up to the `long` range. Title case capitalises each word and each hyphenated part (`Twenty-One`). | The spec does not prescribe the wording; this matches common English usage. |
| XSLT 2.0 §12.3 `ordinal` | English ordinals | Any non-empty `ordinal` value requests English ordinals: `1st 2nd 3rd 4th 11th 12th 13th`, words `first … twelfth … twenty-first`. Ordinals are ignored for alphabetic and roman tokens. | Unsupported combinations produce cardinals (spec permits). |
| XSLT 2.0 §12.3 `i` / `I` | Range of roman numerals | 1 to 3999, subtractive form (`IV`, not `IIII`). Numbers outside the range use the token `1`. | Spec requires an upper bound of at least 1000. |
| XSLT 2.0 §12.3 `a` / `A` | Alphabetic sequences | The 26-letter Latin sequence `a … z aa ab …`, lower bound 1. `letter-value` is accepted and ignored. | `traditional` sequences exist only for other alphabets. |
| XSLT 2.0 §12.3 other tokens | Supported numbering sequences | Every token that is a decimal digit family (any Unicode `Nd` digit whose value is 1, with zero padding), plus the single-character sequences in `SpecialSequences.cs`: circled, parenthesised and full-stop digits (with the zero elements ⓪ ⓿ 🄀 🄁 🄋 🄌 where Unicode defines them), dingbat digits, double-circled, ideograph, Aegean, Sinhala archaic, Rumi, Mende Kikakui, counting-rod, Coptic Epact and Brahmi numbers. Any other token, or a number outside a sequence's range, uses the token `1`. | The spec leaves the repertoire open and requires the fallback. Each table entry is checked against the runtime's Unicode numeric values by a unit test. |
| XSLT 2.0 §12.1 | Values beyond 64 bits | `xsl:number value` converts to `long`; a value that does not fit (such as `1E100`) raises `XTDE0980`. | The spec allows arbitrary-precision integers; revisit if a use case appears. |
| F&O 1.0 §7.6.1 | Regular-expression dialect | The XML Schema 1.0 regex grammar plus `^`, `$`, reluctant quantifiers (`*? +? ?? {n,m}?`), back-references (`\1` and longer, which must refer to an already closed group) and the flags `s m i x`. `(?:…)`, `(?i)`, `\b`, `\A`, `\z`, `\x41`, `A`, octal escapes, lookaround, atomic groups, conditionals, an unescaped `{ } ]` and the flag `q` are `FORX0002` / `FORX0001` (XPath 3.0 or .NET additions). | XSLT 2.0 is defined over F&O 1.0; the QT3 catalog marks `(?:` and `q` as `XP30+`. |
| F&O §7.6.1, XSD Appendix F | `\i`, `\I`, `\c`, `\C` | XML 1.0 **Fifth Edition** `NameStartChar` / `NameChar` ranges. XSD 1.0 refers to the Unicode 2.0 based classes of XML 1.0 (Fourth Edition), which are not reproduced here. | The Fourth Edition tables are large and tied to an old Unicode version; the differences affect a handful of combining characters (three `regex-syntax-xslt20` tests). |
| XSD Appendix F | `\w`, `\W` | `\w` is every code point outside `\p{P}`, `\p{Z}` and `\p{C}` (surrogates excluded), using the Unicode data of the .NET runtime. | Exactly the XSD definition; the data version is the runtime's (newer than Unicode 9). |
| XSD Appendix G | Block escapes | The XML Schema 1.0 block names only (`\p{IsGothic}`, `\p{IsBasicLatin}`, …); a name outside that list is `FORX0002`. Blocks missing from .NET (Old Italic, Gothic, Deseret, the musical and mathematical symbol blocks, CJK Extension B, CJK Compatibility Supplement, Tags) use explicit ranges; `IsPrivateUse` covers `E000–F8FF`, `F0000–FFFFD` and `100000–10FFFD`; the surrogate blocks match nothing. | XML strings cannot contain unpaired surrogates. |
| F&O §7.6.1 | Characters outside the Basic Multilingual Plane | Matched as single characters: `.`, negated classes, `\P{..}`, `\D`, `\S` and ranges all work on whole code points. Category membership for supplementary characters comes from the runtime's Unicode data (on net462 that data predates many supplementary characters). | The language is defined over code points, not UTF-16 units. |
| XSLT 2.0 §4.4 | Conflicting `xsl:strip-space` / `xsl:preserve-space` (XTRE0270) | Recoverable: the declaration that appears last wins, and a compile warning `XTRE0270` is reported when two declarations with the same name test and import precedence disagree. | The spec allows either signalling the error or recovering; recovering keeps stylesheets running. |
| XSLT 2.0 §16.4 | Namespace used for the key name in `key()` | The function has no static context, so a prefixed key name is matched on prefix and local name against the declarations. A stylesheet that binds one prefix to different namespaces in different places may match the wrong key. | Resolving against the call's in-scope namespaces needs the static context to reach the function invoker. |
| XSLT 2.0 §16.6.3 | `system-property()` values | `xsl:version` 2.0, `xsl:vendor` XTransform, `xsl:vendor-url` https://github.com/sfager/xtransform, `xsl:product-name` XTransform, `xsl:product-version` 0.3.0, `xsl:is-schema-aware` no, `xsl:supports-serialization` yes, `xsl:supports-backwards-compatibility` no (becomes yes with P4-25), `xsl:supports-namespace-axis` no. Any other `xsl:` property and any property in another namespace is `""`. | The spec requires these names; the values describe this processor. |
| XSLT 2.0 §16.6.4 | Format of `generate-id()` | `d<tree number><kind letter><index>` (kind `n` node, `a` attribute, `s` namespace), for example `d3n12`. Unique within a run, stable for the same node, not stable across runs. | The spec only requires an NCName that is unique per node. |
| XSLT 2.0 §16.2 | `unparsed-text()` without an encoding | A byte-order mark is honoured; otherwise UTF-8. Invalid bytes, characters not allowed in XML, a fragment identifier, or an unreadable resource raise `FOUT1170`. | F&O §14.2 leaves the autodetection details to the implementation. |
| XSLT 2.0 §16.6 | `unparsed-entity-uri()` / `unparsed-entity-public-id()` | Always the empty string for now: DTD entity declarations do not reach the tree (P4-20). | That is the specified result for an undeclared entity. |
| XSLT 2.0 §16.4.4 | Digits of a double passed to `format-number` | The shortest round-trip decimal digits of the value (`R` format) are expanded to plain digits and then rounded half-to-even; the exact binary value is not used. | The spec says to convert to xs:decimal choosing the numerically equal value with the fewest digits, which is this. |
| XSLT 2.0 §16.4 | `format-number` with a non-numeric first argument | `XPTY0004`. In backwards-compatibility mode the argument would become NaN; that arrives with P4-25. | The 2.0 signature requires a numeric value. |
| XSLT 2.0 §3.7 | `XTSE0090` on `xsl:decimal-format` | Only the decimal-format properties, `name` and the standard attributes (`use-when`, `xpath-default-namespace`, `exclude-result-prefixes`, `extension-element-prefixes`, `version`) are accepted; other un-namespaced attributes (such as the XSLT 3.0 `exponent-separator`) are an error. | Unknown-attribute checking for other elements arrives with P4-23. |
| Serialization 1.0 §6 | Characters the output encoding cannot represent | In `xml` output they are written as numeric character references (`&#8240;`). Other methods are unchanged for now (`html` / `xhtml` arrive with P4-17; the `text` method must raise `SERE0008` and does not yet). | Serialization requires it for the markup methods. |
| XSLT 2.0 §16.5.2 | Language, calendar and country arguments of the date functions | Only English and the Gregorian calendar (`AD`, `CE`, `ISO`) are implemented. Any other language is formatted in English with a `[Language: en]` prefix; any other valid calendar uses `AD` with a `[Calendar: AD]` prefix; a calendar name that is not a lexical QName is `XTDE1340`. The country is ignored. | The spec allows a fallback if the output says so. |
| XSLT 2.0 §16.5.1 | Names, abbreviations and numbering in date pictures | English month and day names; with a maximum width of 5 or less the conventional abbreviations (`Mon`, `Tues`, `Weds`, `Thurs`, `Fri`, `Sat`, `Sun`, `Sept`, … (cut to the maximum)), otherwise right-truncation. The numeric day of week is ISO (Monday = 1). `W` is the ISO week of the year; `w` is the week in the month, where week 1 holds the month's first Thursday and earlier days belong to the previous month. `Z` is `+hh:mm`, `z` is `GMT+hh:mm`; the modifier `0` or a maximum width of 2 gives the short forms `+h` and `+h:mm`. A zone component on a value with no time zone produces nothing. `P` is `am` / `pm`. | The spec leaves these implementation-defined. |
| XSLT 2.0 §13.1.1 | Collation of `xsl:sort` without a `collation` attribute | Unicode codepoint order. If `lang` or `case-order` is given, a culture-sensitive comparison from .NET (`CompareInfo` of the language, invariant culture if the language is unknown); `case-order` then decides between strings that differ only in case. Only the codepoint collation URI is accepted in `collation` (any other is `XTDE1035`) until P4-05. | The spec leaves the default collation and the effect of `lang` implementation-defined. |
| XSLT 2.0 §13.1.1 | `stable="no"` | Accepted and validated; sorting is always stable. | A stable sort is a valid implementation of "no". |
| XSLT 2.0 §14.3 | Equality of grouping keys | Keys are equal under `eq` with `xs:untypedAtomic` as `xs:string` and NaN equal to itself. Strings, anyURI, booleans and numbers are grouped through a hash (numbers of different types that are equal share a group; a number is compared through its exact integer value, or through its `double` value when it has a fraction); dates, times and durations are compared one group at a time with `eq`. Mixed-precision numeric keys (erratum E25 non-transitivity) can be grouped differently from other processors. | The spec allows either result when `eq` is not transitive. |
| XSLT 2.0 §14.3 | Collation of `xsl:for-each-group` | Only the codepoint collation (the default); any other `collation` URI is `XTDE1110`, until P4-05. | Collations arrive with P4-05. |
| F&O §10.4 | Implicit time zone in comparisons of dates and times | A value without a time zone is taken to be in UTC. Years with more than nine digits are compared by their components. | The dynamic context's implicit time zone does not yet reach the comparison operators. |
| XSLT 2.0 §6.4 | `XTRE0540`: more than one matching template rule with the same import precedence and priority | Recovered: the rule declared last wins, with no warning. The conformance suite has paired tests (`…a` expects the recovered result, `…b` expects the error); raising the error fixes 12 and breaks 15, so recovery is the default. A policy option can switch it later. | The spec makes this a recoverable error. |
| XSLT 2.0 §6.7 | Rules reached by `xsl:apply-imports` | Rules whose import precedence lies in the range of the modules imported (directly or indirectly) by the module of the current rule, in rank order; an `xsl:include`d module counts as part of its includer. When none matches, the built-in rule runs. | Follows the post-order precedence numbering of §3.11.3. |
| XSLT 2.0 §6.4 | Alternatives of a union pattern in `xsl:next-match` | Alternatives of one template that share an explicit `priority` attribute are one rule (so a template is not re-entered through its other alternative); alternatives with default priorities are separate rules, even when those priorities are equal. | Matches the results the suite expects for both cases. |
| XSLT 2.0 §11.4.3 | Separator of `xsl:value-of` with a content body | Zero-length when the content form is used, a single space with `select`; the attribute is an AVT. | Both defaults are in the specification. |
| XSLT 2.0 §5.7.1, §5.7.2 | Text nodes and zero-length text nodes in a sequence | In a sequence (an `as` variable, a function result) `xsl:value-of`, `xsl:text` and `xsl:number` each give a separate text node, and a zero-length one is kept; `xsl:value-of` then drops zero-length text nodes from the sequence it joins. A top-level attribute node is built inside a throw-away element, so `parent::node()` on it is not empty. | Needed to give typed variables the items the spec describes. |
| XSLT 2.0 §9.2 | `as` on a parameter with no default | The empty sequence, which the type must allow; otherwise the parameter is treated as required and `XTDE0610` is raised when it is not supplied. | The error code for a missing required parameter is `XTDE0700`; `XTDE0610` is the one the spec gives for this case. |
| XSLT 2.0 §6.4 | Default priority of the pattern `/` | -0.5 (as `document-node()`); every other pattern with a `/` or a predicate keeps 0.5. | The conformance test `conflict-resolution-1601` requires it. |
| XSLT 2.0 §5.2 | `xpath-default-namespace` on a literal result element | The `xsl:xpath-default-namespace` form applies from that element down; the value is trimmed. | Same inheritance as on XSLT elements. |
| XSLT 2.0 §16.4 | `key()` on a constructed element that has no parent | `XTDE1270` is raised when there is no context node; a constructed element (a variable with `as="element()"`) reports a document node as its parent, so a node whose tree root is not a document node is not detected. | The tree model roots every constructed tree at a document node. |
| XSLT 2.0 §3.6.1, §16.3 | Which collations are recognised | Only the Unicode codepoint collation. A `default-collation` list with no recognised URI is `XTSE0125` and an `xsl:key` `collation` that is not recognised is `XTSE1210`. | No other collation is implemented yet (P4-05 widens the list in `CollationUris`). |
| XSLT 2.0 §16.3 | `xsl:key` with content instead of a `use` attribute | Reported as `XTSE0010` ("not supported"); having both, or neither, is `XTSE1205`. | The content form is valid XSLT 2.0 but is not built. |
| XSLT 2.0 §11.3.1 | Prefix of an `xsl:attribute` in a namespace | The prefix written in the name when the stylesheet does not bind it to another namespace; otherwise, and when the name has none, a generated one (`ns0`, `ns1`, ...) that the stylesheet does not bind where the instruction is. | An attribute in a namespace needs a prefix and the specification leaves the choice open. |
| XSLT 2.0 §5.7.1 | A prefix that clashes with a namespace node of its own element | The serializer gives the element or attribute a free prefix (`ns0`, `ns1`, ...) and declares the namespace it needs. | Namespace fix-up; the choice of prefix is implementation-defined. |
| XDM §6.2 | Namespace nodes of an element | Stored once, on the element that declares them (the outermost element declares `xml`), and inherited by its descendants, so `generate-id()` of an inherited namespace node is the same on every element that inherits it. The serializer never declares the `xml` prefix. | The tree model has no per-element namespace nodes. |
| XSLT 2.0 §11.1.4 | `xsl:namespace-alias` with `result-prefix="#default"` and no default namespace | The result namespace is the null namespace, and the aliased namespace node is left out. | A namespace node needs a value. |
| XSLT 2.0 §20 | XML 1.1 namespace undeclaration (`xmlns:p=""`, `undeclare-prefixes`) | Not produced. A prefix declared on an ancestor stays in scope on descendants that do not use it, so `inherit-namespaces="no"` does not undeclare it. | Needs XML 1.1 output; tests that expect it (`namespace-2603` to `2610`) stay known failures. |
| XSLT 2.0 §3.2, XML Base | Base URI of a node | `xml:base` is resolved against the base URI of the parent and kept as one value per element; attributes, text, comments and processing instructions take their parent's; namespace nodes have none. A stylesheet element's static base URI is its module URI changed by `xml:base` on it or an ancestor (so `static-base-uri()`, `resolve-uri()`, `document()` and `doc()` see the base at the call, not just the principal module). | Follows XML Base and the Data Model; the module URI is the stylesheet's absolute URI when it has one. |
| XSLT 2.0 §11.9, XDM | Base URI of a constructed node | The document node built from a variable's content takes the static base URI of the `xsl:variable`; an element copied with no parent keeps the base URI of the original; a copy inside a constructed parent takes the parent's; an attribute, text, comment or processing-instruction node with no parent has none. | The specification leaves it to the data model; this matches what the test suite expects. |
| XSLT 2.0 §16.1 | `document()` | A relative reference is resolved against the base URI of the node argument, the second argument, or the static base URI at the call; a node with no base URI falls back to the static base URI. A fragment identifier is dropped (the whole document is returned). A resource that cannot be read is skipped (XTRE1160 recovery). The result is in document order without duplicates. | Fragment identifiers and retrieval failures are implementation-defined. |
| XML 1.0 §4 | DTDs in source documents and stylesheets | Parsed (`DtdProcessing.Parse`) with no resolver, so internal entities and the internal subset work, the external subset and external entities are never read (no XXE), and entity expansion is capped at 10,000,000 characters. | Security: no external resources are fetched while reading a document. |
| XSLT 2.0 §16.6.4 | `unparsed-entity-uri()`, `unparsed-entity-public-id()` | Read from `<!ENTITY ... NDATA ...>` declarations in the internal subset only (`System.Xml` does not expose them); the system identifier is resolved against the document's base URI. A context item that is not in a document-rooted tree is `XTDE1370` / `XTDE1380`. | The external subset is not read. |
| XML 1.1 | Documents that declare version 1.1 | A source or stylesheet that begins with a seekable `<?xml version="1.1"?>` is read as 1.0 with character checks off, so character references to control characters work; the wider 1.1 name characters and namespace undeclaration (`xmlns:p=""`) are not supported (`System.Xml` rejects them), which leaves about a third of the `xml-version` tests as known failures. `xsl:output version="1.1"` writes the 1.1 declaration and control characters (C0 except tab and line feed, and C1) as character references. | `System.Xml` has no XML 1.1 parser. |
